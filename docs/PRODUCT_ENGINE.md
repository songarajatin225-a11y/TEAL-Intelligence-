# Product engine

Covers the product portfolio, Configurator 2.0, the inquiry → product workflow and the BOM.

## 1. Portfolio

`data/products/platforms.json` — 22 TEAL platforms in 7 families (`product-families.json`),
migrated from the legacy simulator and the TEAL catalogue: sources, power classes per source,
objectives, standard content, specifications, industries, applications (76 in
`data/applications/applications.json`), lead time, warranty, installation, **base price
(ESTIMATE)** and maturity. *Products* shows the portfolio; each product opens its **Product DNA**
(every field linked through the thread, UNKNOWN where nothing exists) and *Platformization*
compares custom work against standard platforms.

## 2. Configurator 2.0 (`src/features/configurator/engine.ts`)

`ConfiguratorEngine` is the legacy simulator's logic as a pure class:

| Method | Legacy | Behaviour |
|---|---|---|
| `initialState`, `withApplication`, `withSource` | defaults, `stdSeed`, `snapPower`, `powersFor` | platform defaults, standard content preselected, power snapped to the source's classes |
| `modFits` | `modFits()` | family / delivery / material gates for each module |
| `conflicts` | `modConflicts()` | 7 exclusive pairs, now data (`module-conflicts.json`) |
| `price` | `price()` | parametric ex-works estimate with breakdown and band: platform base → power scaling vs. the default power → source premium ratio → large-objective uplift → + non-standard modules and extras (standard content never charged twice) — labelled ESTIMATE |
| `designation` | `desig()` | `TEAL-<code>-<src>-<W>-<lens>-<nn>M-<sw>` |
| `recommendations`, `applyRecommendation` | `evalReco()` | 27 rules; each hit carries its rule for WHY? |
| `physics` | `optics()`, `physics()` | spot, depth of focus, pulse energy, peak power, fluence, irradiance, regime, absorptance, thermal diffusion, wall-plug, cooling — each a `CalcResult` citing Automation Handbook Part 54 (L1–L11) |
| `compatibility` | — (new) | OK / WARNING / FAIL / UNKNOWN per check |
| `legacyHash` | `encodeState()` | same URL hash → *Open in 3D simulator* opens the embedded legacy app in the identical state |

Parity: 7 golden cases generated by executing the legacy code (`tests/unit/configurator.test.ts`).
Saved configurations keep a snapshot (price + physics) and versions (`parent_id`); the record
view shows drift when current data would price it differently.

## 3. Create product from customer inquiry (`src/services/inquiry.ts`)

1. **Parse** (`parseInquiry`) with the migrated lexicon (+3 OS additions, recorded in
   `_os_additions`): process families, materials, needs (handling, vision, MES …), cares (heat,
   medical …), scale, parts/hour, industry, *customer supplies laser*.
2. **Match** (`matchPlatforms`) — per platform application: process terms ×10 (credited for the
   process the platform's applications perform, not only its family), specialist platform +10,
   material ×9, industry +8, wording +3 per shared term, low-heat +7, regulated +5, throughput or
   low-volume +5. Top 3 with reasons.
3. **Draft package** (`buildDraftPackage`) — opportunity, requirements (rules per detected need,
   each with verification method), application, process candidates, configuration of the top
   match, POC, DOE plan (factors/responses, no results), preliminary BOM and cost model
   (via `bomGen`), supplier needs with candidate suppliers, risks, open questions, G0 checklist,
   project skeleton with tasks. All `INFERRED` / `DRAFT`; the opportunity value is `null`.
4. **Save** — one all-or-nothing batch of local drafts; an optional new customer is created in
   the same batch.

Scenario 1 of the final demo selects **Semi SPM** (score 100) and adds the free-issue laser
requirement; asserted in `tests/integration/inquiry.test.ts`.

## 4. BOM (`src/services/bomGen.ts`, `src/features/bom/`)

Configuration → preliminary EBOM: L001 platform standard machine (ESTIMATE), laser source
(UNKNOWN — included in the platform estimate — or 0 when customer-supplied), objective, and one
line per module/extra/software (list-price ESTIMATE, or 0 as standard content). BOM view: tree,
make/buy, lead time, risk, alternates, totals by cost basis, **Generate RFQ**, **Cost model**,
**Localization candidates** (import items), CSV export.

## 5. Machine architecture (`src/features/machines/ArchitecturePage.tsx`)

`deriveArchitecture` turns a configuration into a node graph (laser, optics, galvo, motion, robot,
vision, PLC, IPC, HMI, safety, fixture, conveyor, chiller, fume extraction, inspection, MES) that
can be edited and rearranged; the layout is stored per configuration in local preferences.
